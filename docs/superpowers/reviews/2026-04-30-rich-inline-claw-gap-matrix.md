# Rich Inline TUI Claw-Code Gap Matrix

This review compares Astra's current TUI against the Claw-Code Rust CLI under `reference_repos/requested/claw-code/rust/crates/rusty-claude-cli/src`. The acceptance bar is a scrollback-native rich inline code-agent UI, not a fullscreen dashboard and not a bare readline prompt.

| Area | Claw behavior | Current Astra behavior | Required fix | Acceptance test |
|---|---|---|---|---|
| Default product shape | `claw` starts a scrollback-native REPL: banner, status, readline prompt, rich markdown/tool output. It does not enter alternate screen for normal coding. | `astra` defaults to inline, but the visible UI is mostly a banner plus `rustyline`; the richer palette/composer UI exists mainly in fullscreen/test render paths. | Keep default non-fullscreen, but make it rich inline: startup status, visible composer frame, visible command/skill palette, markdown/tool cards. Fullscreen remains explicit `--fullscreen`. | `astra` in an interactive PTY shows rich inline composer/palette; `astra tui launch --fullscreen --json` still reports fullscreen mode. |
| Line editing | Claw `LineEditor` uses `rustyline`, Emacs mode, history, Tab list completion, Ctrl-J/Shift+Enter newline, Ctrl-C clears input or exits when empty, non-TTY fallback. | Astra has a copied inline line editor for basic readline and a separate fullscreen byte-input path. Rich composer state is not unified with inline display. | Preserve `rustyline` quality, but add Astra-specific rich inline preview/palette around it. Do not regress multiline/history/non-TTY behavior. | Unit tests for multiline preservation, dynamic candidates, plain prompt vs `/` command vs `$` skill routing; PTY smoke for `/`, `$`, Tab, Ctrl-C. |
| Slash completion | Claw completions are generated from one command registry plus aliases and dynamic model/permission/session candidates. | Astra has command specs and dynamic model/reasoning candidates, but current inline only exposes them through bare completion list; visible descriptions are not shown in inline. | Add visible inline slash palette with command, localized label, group/category, summary, selected row, and scroll window. | Rendering test for `render_rich_inline_prompt_frame` with composer `/` contains selected row, Chinese labels, descriptions, and not debug-only commands. |
| Skill invocation | Claw routes skill-like commands through explicit command dispatch and avoids forwarding known control input to the model. | Astra has `$` skill prefix and fullscreen/test palette; current inline does not present a rich skill dropdown. | Add visible `$` palette with skill id, summary, selected row, scroll window, and `$list` guidance. | Rendering test for composer `$research` shows matching skills and selected styling; route test proves `$skill` does not invoke prompt executor. |
| Plain text prompt routing | Claw sends non-command text into `run_turn`. | Astra now sends plain text into runtime, which is correct. | Preserve this while improving UI. `/` and `$` must never become model prompts unless explicitly `/prompt` text. | Existing `tui_prompt_payload_or_plain_text` and streaming prompt tests keep passing. |
| Streaming markdown | Claw buffers markdown deltas until safe boundaries and renders headings/lists/code/tables with crossterm styling. | Astra has `TerminalMarkdownRenderer` and `MarkdownStreamState`, but current inline output is visually sparse and metadata can look like debug lines. | Use markdown renderer in rich inline output; render deltas progressively, flush code fences safely, suppress duplicate final body. | Unit tests for streaming deltas and code fence boundaries; smoke prompt shows token-level incremental output. |
| Tool blocks | Claw formats tool calls/results as compact semantic cards: bash/read/write/edit/search with truncation notices. | Astra primarily parses legacy text into generic blocks; provider boundary still lacks real tool-use events. | Short term: render available `tool:`/status/research lines as cards. Long term blocker: provider/runtime must emit structured tool events. | Tests classify tool/status lines into `Tool`/`Status`; gap remains documented until runtime emits true tool events. |
| Permission prompts | Claw permission prompt appears only when a tool needs approval and shows tool/current mode/required mode/reason/input. | Astra has real `/approve`/`/deny` executor actions, but permission controls can still feel like global commands rather than contextual cards. | Render pending permission as a conversation card when present; default status shows permission mode only, not fake approval UI. | Unit test for permission line/card classification; no default startup approval control without pending request. |
| Prompt history | Claw persists and renders prompt history; readline history works naturally. | Astra has current TUI prompt history and `/history`, but it is not a full persistent transcript viewer. | Keep current prompt history, ensure inline readline/history remains; future work can hydrate session transcript into TUI. | `/history` tests keep passing; PTY history smoke where feasible. |
| Model/reasoning commands | Claw exposes `/model` and `/permissions` dynamic completions. | Astra `/model` and `/reasoning` are real config executor actions and update state. | Preserve real executor binding; visible palette should include model/reasoning argument candidates and clear Chinese copy. | `/model gpt 5.5` and `/reasoning high` executor tests keep passing; palette candidates include recommended values. |
| Session resume | Claw supports resume latest/session switch and persists session state. | Astra `/resume latest|id` now calls runtime session store and updates active session for following prompts. | Preserve this; visible `/sessions`/`/resume` palette should expose recent sessions. | Existing resume/session tests keep passing; runtime smoke `/sessions` returns real session list. |
| Research status | Claw has coding-focused startup/status; Astra must add research without overexposing internals. | Astra currently surfaces research line but often as plain text. | Rich inline status strip should show topic/thread and stage only when useful; no large research dashboard in first-level chat. | Startup rendering test contains compact research strip, not debug IDs or giant research copy. |
| Non-TTY fallback | Claw falls back to one-line read or script-safe behavior when stdin/stdout is not TTY. | Astra non-TTY currently returns deterministic plain text, useful for tests. | Preserve script-friendly non-TTY fallback. Do not judge interactive UI quality from non-TTY snapshot. | `printf '/help\n' | astra tui launch` remains deterministic and ANSI-light. |
| Launch metadata | Claw has one default REPL. | Astra JSON reports `inline_projection_renderer`, but this does not distinguish bare inline from rich inline. | Add/adjust metadata to make default mode explicit: rich inline terminal, fullscreen only when requested. | Operator/conformance tests assert rich inline metadata and fullscreen metadata separately. |

## Acceptance Gate

The TUI is not acceptable if any of these are true:

- Default interactive `astra` looks like a plain debug prompt with only a few text lines.
- `/` or `$` only works as hidden completion and does not show visible command/skill choices.
- Plain text does not go through the real runtime prompt path.
- `/model`, `/reasoning`, `/resume`, `/approve`, `/deny` regress to fake staged text.
- Streaming output duplicates final body or drops partial deltas.
- Fullscreen becomes the default coding UI.
