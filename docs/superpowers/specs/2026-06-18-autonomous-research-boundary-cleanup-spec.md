# 全自动研究边界清理与产物交接闭环规格

日期：2026-06-18

对应 PRD：`docs/superpowers/specs/2026-06-18-autonomous-research-boundary-cleanup-prd.md`

## 总体方案

本规格不是新增一套任务系统，也不是新增一套产物交接系统，而是清理现有实现中的并行路径，并把现有产物推进路径统一解释为“黑盒输出 -> 候选 -> 主代理决策 -> 已接受证据 -> 阶段候选 -> 采纳 -> 落地 -> 评审 -> 阶段关闭”。

这条链必须复用现有主干：worker 输出和 candidate manifest、worker artifact decision、accepted evidence index、canonical artifact ledger、review packet、stage closure ledger。新增代码只能做统一读模型、转换函数、校验函数或兼容适配，不能新增与这些对象并列的持久权威。

核心改造有四类：

1. 清理并行任务契约推导。
2. 降级运行层任务候选为事实投影。
3. 将现有对象收束为统一产物交接状态读模型。
4. 将工具层校验改为产物交接边界校验，而不是研究路线校验。

## 当前实现问题点

### 并行任务契约

当前至少有以下契约形态：

- `GoalStageTaskMetadata`：位于 `src/goals/mod.rs`，用于任务池和看板投影。
- `AgentStageTaskContract`：位于 `src/agents/mod.rs`，用于子代理任务包。
- 阶段证据计划：通过 `record_stage_evidence_plan` 写入。
- 看板任务：通过 `publish_board_tasks` 和 `update_board_task` 写入。
- 自动研究阶段任务目录：位于 `src/runtime/mod.rs` 的提示投影和默认建议。

这些对象字段相似，但没有单一转换边界。结果是同一个任务在不同位置被重新解释。

### 错误输出映射

`src/goals/mod.rs` 中的 `stage_required_output_artifact_type_for_task` 当前逻辑是：

- 验收标准任务输出 `stage_acceptance_rubric`。
- 其他任务输出阶段最终产物。

这会把局部任务错误声明为阶段产物任务。

`src/runtime/mod.rs` 中又存在另一套更细的 `autonomous_research_stage_task_required_output_artifact_type`，两者不一致。

### 任务候选越界

`build_missing_stage_task_pool_entries` 会产生 `research_stage_task_candidate`，并携带任务类型、角色、输出类型和建议命令。虽然提示词说这不是调度授权，但它已经接近任务设计。

运行层应投影事实，例如“缺少某类已接受证据”或“没有可采纳阶段候选”，而不是投影完整任务候选。

### 工具层校验不足

`validate_board_task_publication_contract` 主要检查字段非空。

已有校验包括：

- 综合任务必须由 `research_synthesizer` 执行。
- 修复任务输出类型不能是 `artifact_repair`。
- 消费上游证据的任务需要依赖声明。

缺失的是产物交接边界校验：

- 候选输出不能直接当作已接受证据。
- 非主代理采纳不能落地规范项目文件。
- 未经主代理接受的输入不能用于阶段综合。
- 输出产物的状态必须明确，而不能只靠 `required_output_artifact_type` 字符串推断。

### 输出校验按产物名硬判

`src/agents/mod.rs` 中的输出校验看到 `literature_matrix` 就要求行级文献矩阵字段。因为上游会把局部任务错误声明为 `literature_matrix`，导致局部任务被最终产物校验打死。

输出校验应改为基于产物交接状态和候选类型，而不是只基于最终产物名。

## 现有状态的统一读模型

抽象一个统一的产物交接状态枚举或读模型。名称可以在实现时调整，但它只能从现有记录推导，不能成为新的独立持久账本。语义必须完整：

- `worker_candidate_output`：子代理黑盒输出，尚未通过机械结构检查。
- `structurally_valid_candidate`：运行层确认来源、路径、基本结构可读。
- `pending_main_agent_decision`：候选等待主代理语义接受、拒绝或延期。
- `main_agent_accepted_evidence`：主代理接受为当前阶段可用证据。
- `main_agent_rejected_candidate`：主代理拒绝，不能再被自动采纳。
- `synthesis_candidate`：由黑盒根据已接受证据生成的阶段候选产物。
- `adopted_stage_artifact_candidate`：主代理选择采纳的阶段候选。
- `materialized_canonical_artifact`：运行层已机械落地到规范项目路径。
- `integration_verified_artifact`：运行层完成路径、引用、格式、索引一致性检查。
- `reviewed_stage_artifact`：评审代理完成严格评审。
- `stage_closure_ready`：主代理可基于评审和证据关闭阶段。

该模型不决定研究路线，只决定产物在现有状态主干中最多已经推进到哪里，以及下一步是否缺主代理语义决策、机械校验、采纳、落地或评审。

### 禁止新增并行交接

实现时必须遵守：

1. 不新增与 accepted evidence index 并列的 `artifact_handoff_index` 一类持久账本。
2. 不新增与 canonical artifact ledger 并列的阶段产物采纳账本。
3. 不让统一读模型主动推进状态；状态推进仍由现有工具和记录完成。
4. 不让统一读模型生成科研任务；它只把现有事实投影给主代理。
5. 如果必须补字段，应优先补到现有记录对象中，而不是新建一套对象。

## 代码改造规格

### 一、收敛任务契约转换边界

目标：不要再让多个模块独立推导同一任务的输出语义。

实施要求：

1. 保留 `GoalStageTaskMetadata` 和 `AgentStageTaskContract` 作为数据结构，但新增显式转换函数：
   - 从看板任务生成 `GoalStageTaskMetadata`。
   - 从 `GoalStageTaskMetadata` 生成 `AgentStageTaskContract`。
   - 不允许 `runtime` 和 `agents` 再自行重新解释输出类型。
2. 清理或改造 `stage_required_output_artifact_type_for_task`：
   - 不能再默认把所有非验收标准任务映射为阶段最终产物。
   - 如果无法可靠确定输出状态，应使用候选证据类状态，而不是阶段最终产物。
3. `autonomous_research_stage_task_required_output_artifact_type` 不能作为另一套权威映射。
   - 它可以保留为显示辅助或兼容层。
   - 主路径必须以主代理发布到看板的任务和产物交接状态为准。

### 二、运行层任务候选降级为事实投影

目标：运行层不生成科研任务候选。

实施要求：

1. `research_stage_task_candidate` 不应再携带完整任务合同。
2. 任务池中由运行层投影的缺口应表达为事实：
   - 缺少某类已接受证据。
   - 有候选待主代理处理。
   - 有失败评审未处理。
   - 没有可采纳阶段产物。
   - 阶段不能关闭的机械原因。
3. 主代理如果要派任务，必须自己调用 `publish_board_tasks` 或 `update_board_task` 写入看板。
4. continuity packet 中应清楚标注：
   - 事实投影不是任务。
   - 看板任务才是可派发任务。

### 三、工具层改为边界校验

目标：工具层不做科研决策，但守住产物交接边界。

实施要求：

1. `publish_board_tasks` 和 `update_board_task` 写入看板前必须校验：
   - 任务是否声明了输出状态类别。
   - 如果声明阶段候选产物，是否有已接受证据输入或明确说明为何不需要。
   - 如果声明要落地规范项目文件，必须拒绝；落地只能通过采纳工具完成。
   - 如果任务消费上游证据，输入引用必须可解析或形成阻塞。
2. 工具层不判断“文献阶段下一步该做什么”。
3. 工具层不禁止主代理发布大任务，但要确保大任务的产物最多进入候选状态，不能跳过主代理接受和采纳。
4. 允许主代理发布综合型任务，但该任务输出仍只是候选，不能自动成为规范项目文件。

### 四、输出捕获按现有状态主干推进

目标：黑盒子代理输出进入系统时，先成为候选，而不是直接成为已接受证据。

实施要求：

1. 子代理完成后，运行层继续写入现有 worker 输出、manifest 和候选产物记录，并在统一读模型中投影为 `worker_candidate_output`。
2. 机械检查通过后，在现有候选记录或检查记录中表达结果，并投影为 `structurally_valid_candidate`。
3. 只有主代理调用现有决策工具或其兼容扩展，才能投影为 `main_agent_accepted_evidence` 或 `main_agent_rejected_candidate`。
4. 运行层不得通过重放、回放或质量分数自动把候选升为已接受证据，除非存在明确主代理历史决策记录。
5. 已接受证据必须能追溯到：
   - 原始任务包。
   - 子代理输出。
   - 候选产物路径。
   - 结构检查结果。
   - 主代理决策记录。

### 五、阶段产物采纳路径收束

目标：阶段产物只能从明确候选经过主代理采纳和运行层机械落地进入规范目录。

实施要求：

1. `adopt_stage_artifact` 只能接受从现有记录可追溯为可采纳状态的候选。
2. 候选必须来自隔离工作区或已记录的候选产物，不允许主代理自由文本伪造路径。
3. 采纳后运行层只做机械落地，不修改科研内容。
4. 落地后写入集成检查记录。
5. 评审只评审落地后的规范项目文件和其证据索引。

### 六、主代理上下文改造

目标：主代理看到的是产物交接状态，而不是混杂任务建议。

continuity packet 需要新增或强化以下段落：

- 当前候选输出。
- 结构有效候选。
- 待主代理决策候选。
- 已接受当前证据集。
- 被拒绝或废弃候选。
- 可采纳阶段候选。
- 已落地规范产物。
- 集成验证结果。
- 评审结果和未闭合阻塞。

主代理提示词需要强调：

- 运行层投影的是事实，不是任务建议。
- 看板任务必须由主代理语义设计。
- 子代理黑盒输出只代表候选。
- 不要把单个失败任务无限加重；应先判断候选交接状态和证据缺口。

## 清理清单

必须扫描并清理以下类型代码：

1. 将非验收标准任务默认映射为阶段最终产物的逻辑。
2. 在运行层生成完整科研任务候选的逻辑。
3. 同一任务输出类型在 `goals` 和 `runtime` 两处独立推导的逻辑。
4. 只按产物名硬编码校验，而不看候选状态的输出校验。
5. 角色技能文档中暗示普通局部代理应产出阶段最终规范产物的表述。
6. 自动重放旧证据为当前已接受证据但缺少主代理决策记录的路径。
7. 会让 `publish_board_tasks` 或 `update_board_task` 成为“一次调用即强制交接”的硬逻辑；需要评估是否改为显式交接，避免主代理无法完成事务式编排。

## 测试要求

至少新增以下测试：

1. 局部任务不会被默认映射为阶段最终产物。
2. 运行层缺口投影不包含完整任务合同。
3. 子代理输出先成为候选，不会自动进入已接受证据。
4. 没有主代理决策记录时，候选不能被采纳为阶段产物。
5. `adopt_stage_artifact` 拒绝未通过候选链的路径。
6. 主代理发布综合任务后，产物仍需经过候选、接受、采纳、落地、评审。
7. 黑盒子代理输出格式不完美时，系统能保留候选和阻塞，而不是重复加重同一任务。
8. 长跑模拟中，失败的文献候选会投影为交接缺口，不会自动生成重复 `paper search` 巨型任务。

## 验收标准

完成本任务后：

- 代码中应能明确指出任务记录、事实投影、候选产物、已接受证据、规范项目文件分别由谁产生、谁判断、谁落地。
- 看板不承担裁判职责。
- 运行层不承担任务设计职责。
- 主代理能看到完整产物状态链。
- 子代理可替换为黑盒外部代理而不破坏状态推进。
- 旧的并行契约推导被清理或降级，不再影响主路径。
