# 全自动研究边界清理与产物交接闭环实施计划

日期：2026-06-18

对应文档：

- `docs/superpowers/specs/2026-06-18-autonomous-research-boundary-cleanup-prd.md`
- `docs/superpowers/specs/2026-06-18-autonomous-research-boundary-cleanup-spec.md`

## 目标

清理当前全自动研究中的并行任务契约和影子状态机，把现有系统收束为：

主代理做科研语义决策；看板记录任务；运行层投影事实和守机械边界；子代理作为黑盒产出候选；产物通过统一交接链进入已接受证据、阶段候选、规范项目文件和评审。

这里的统一交接链不是新建持久系统，而是对现有 worker 输出、candidate manifest、worker artifact decision、accepted evidence index、canonical artifact ledger、review packet、stage closure ledger 的收束和统一解释。

## 实施原则

1. 不新增第二套自动研究流程。
2. 不新增第二个看板或任务池。
3. 不固定文献阶段任务链。
4. 不试图控制黑盒子代理内部行为。
5. 不让运行层生成科研任务。
6. 每次改动都要删除或降级旧路径，避免新协议继续叠在旧逻辑上。
7. 不新增与 accepted evidence index 或 canonical artifact ledger 并列的产物交接账本。

## 阶段一：现状锁定和失败测试

### 目标

先用测试固定当前错误，避免重构变成新补丁。

### 任务

- 添加测试证明局部任务当前会被默认映射为阶段最终产物。
- 添加测试证明运行层候选任务当前携带完整任务合同。
- 添加测试证明字段非空校验无法阻止候选产物跳状态。
- 添加测试证明子代理输出可以绕过明确主代理决策进入已接受证据的风险路径。
- 添加测试证明 `publish_board_tasks` 或 `update_board_task` 的强制交接会打断主代理事务式编排。

### 验收

- 至少四个测试在修复前失败。
- 失败信息能指向 PRD 中列出的混乱根因。

## 阶段二：现有产物交接状态读模型

### 目标

先统一解释现有产物如何进入系统，而不是先重写任务编排，也不是新增第二套交接。

### 任务

- 抽象产物交接状态枚举或读模型。
- 从现有 worker 输出、候选清单、主代理决策、accepted evidence index、canonical artifact ledger、review packet 和 stage closure ledger 推导候选输出、结构有效候选、待主代理决策、已接受证据、拒绝候选、阶段候选、已采纳候选、规范项目文件、集成验证和评审结果。
- 如果现有记录缺少必要字段，优先补字段到现有对象中，不新建并列账本。
- 确保没有主代理决策记录时，任何候选不能进入已接受证据。

### 验收

- 子代理输出能被记录为候选。
- 主代理决策前，候选不会参与阶段关闭门。
- 主代理接受后，候选才进入当前证据集。

## 阶段三：清理并行任务契约推导

### 目标

去掉“同一任务多处解释”的核心混乱。

### 任务

- 改造 `stage_required_output_artifact_type_for_task`，移除“非验收标准任务默认阶段最终产物”的逻辑。
- 降级 `autonomous_research_stage_task_required_output_artifact_type`，使其不再作为权威路径。
- 建立明确转换边界：看板任务 -> `GoalStageTaskMetadata` -> `AgentStageTaskContract`。
- 任务包生成不得重新推导任务语义，只能承接看板任务和主代理决策。

### 验收

- 同一任务不会在 `goals` 和 `runtime` 得到两种输出解释。
- 局部任务默认进入候选证据语义，而不是阶段最终产物语义。

## 阶段四：运行层事实投影降权

### 目标

运行层只告诉主代理事实，不生成科研任务候选。

### 任务

- 修改 `research_stage_task_candidate` 一类投影，移除完整任务合同。
- 将其改为缺口事实，例如“缺少已接受文献证据”“存在待决策候选”“缺少可采纳阶段候选”。
- 更新主代理 continuity packet，明确区分事实投影和看板任务。
- 删除或降级会让运行层像任务设计者的字段和提示。

### 验收

- continuity packet 中运行层投影不再像可直接派发任务。
- 主代理仍能看到缺口，但必须自己发布看板任务。

## 阶段五：工具层边界校验

### 目标

工具层不做研究判断，只阻止状态跳跃和机械越权。

### 任务

- 在 `publish_board_tasks` 和 `update_board_task` 中加入产物状态字段和合法性检查。
- 禁止任务直接声明规范项目文件落地。
- 消费上游证据的任务必须有可解析输入或形成阻塞。
- 阶段产物采纳必须通过 `adopt_stage_artifact`，不能通过看板任务字段绕过。
- 评估强制 `main_agent_turn_complete` 是否改为显式交接或批量事务交接。

### 验收

- 工具层不会评价任务科研合理性。
- 工具层会拒绝状态跳跃。
- 主代理可以在一轮中完成完整编排后再交接。

## 阶段六：输出捕获和采纳链收束

### 目标

让黑盒子代理输出稳定进入候选链，而不是直接参与阶段结论。

### 任务

- 修改子代理完成处理逻辑：先记录候选，再做结构检查，再等待主代理决策。
- 输出校验不再只按 `required_output_artifact_type` 硬判。
- `adopt_stage_artifact` 只接受可追溯候选。
- 采纳后写入机械落地和集成验证记录。
- 评审以规范项目文件和证据索引为目标。

### 验收

- 黑盒输出能保留为候选，即使格式不完美也能形成明确阻塞。
- 没有主代理接受的候选不能成为阶段证据。
- 没有主代理采纳的阶段候选不能成为规范项目文件。

## 阶段七：角色文档和提示词清理

### 目标

去掉普通子代理应直接产出最终阶段产物的旧口径。

### 任务

- 扫描 `src/session/role_packages` 和 `src/session/role_souls`。
- 清理“普通局部代理写最终阶段产物”的表述。
- 保留黑盒输出候选、证据、风险和缺口的要求。
- 主代理提示词改为围绕产物状态链决策，而不是围绕任务候选补丁。

### 验收

- 普通子代理文档不再暗示可以直接落地阶段最终产物。
- 综合代理仍可产出阶段候选，但必须经主代理采纳。

## 阶段八：集成验证和长跑回归

### 目标

证明重构不是文档级修复。

### 任务

- 运行相关 Rust 单元测试和契约测试。
- 编译 CLI。
- 在空目录启动全自动研究长跑。
- 观察文献阶段是否不再无限加重同一任务。
- 检查主代理是否围绕候选状态、已接受证据和阶段候选做决策。

### 验收

- 编译通过。
- 单元和契约测试通过。
- 长跑中能看到候选、接受、综合、采纳、评审状态链。
- 如果阶段仍失败，失败应落在明确交接缺口，而不是重复巨型 `paper search`。
