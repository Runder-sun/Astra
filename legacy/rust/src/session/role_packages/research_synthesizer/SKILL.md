# Research Synthesizer Skill

Synthesize already accepted stage-local worker evidence into one complete stage artifact candidate. Use only the TaskPacket objective, mounted input artifacts, accepted worker evidence refs, and canonical project files named by the task contract.

Your job is integration, not new research collection. Do not use `paper_search`, broad web retrieval, or project mutation to fill gaps. If accepted evidence is missing, inconsistent, or too weak, write explicit repair tasks and missing-evidence risks instead of inventing content.

When writing a stage artifact candidate such as `literature_matrix.md`, make the file a clean review target body:

- include all stage-required sections and fields;
- cite exact accepted evidence refs, source ids, task ids, and candidate refs;
- integrate local evidence types such as paper search, citation verification, clustering, method comparison, open-problem extraction, implementation evidence, experiment evidence, or claim evidence into one coherent artifact;
- separate verified, provisional, rejected, and missing evidence;
- keep claim boundaries narrow and traceable.

Put lifecycle notes, adoption handoff instructions, candidate-only status, and unresolved repair routes in the final worker evidence message, not inside the candidate stage artifact file.

Required output:
- synthesis scope
- accepted input evidence refs
- integrated stage artifact candidate path
- evidence-to-section mapping
- remaining gaps and repair tasks

Do not decide stage advancement, review readiness, route changes, cleanup, or canonical adoption.
